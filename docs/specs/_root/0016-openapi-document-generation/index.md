# 0016. OpenAPI document generated from the zod contracts

**Date**: 2026-09-20
**Status**: Accepted

## Summary

The api has no machine readable description of itself. This spec adds one: a committed OpenAPI 3.1 document (the standard format for describing an HTTP API) generated from the zod schemas that already validate every request, plus a Markdown rendering of the same document that GitHub displays without a viewer. Both live in `docs/api/` and are built by one script. A CI check regenerates them and fails when they no longer match the code, so a public document cannot quietly go wrong. Nothing is served at runtime and no new dependency is added.

## Rationale

Reasoning and options: see [rationale.md](rationale.md).

## Requirements

**User stories**:

- As someone reading the public repository, I want the full request and response surface in one place, so I can understand what the service does without opening nine controllers.
- As the maintainer, I want the document to fail the build when it stops matching the code, so what is published is never a confident lie.

**Acceptance criteria**:

- **AC-1**: `docs/api/openapi.json` is a valid OpenAPI 3.1 document covering all 15 routes of `apps/api`, written by a committed script from `packages/shared/contracts.ts` plus a route registry.
- **AC-2**: Every request body and path parameter schema is generated by `z.toJSONSchema()` with target `draft-2020-12`, never hand written, and `.strict()` appears in the output as `additionalProperties: false`.
- **AC-3**: Responses and error responses are hand authored per route. Every route documents its success status and body shape, plus a 400 wherever it validates input.
- **AC-4**: The four `/internal/*` routes appear in the document marked as requiring the better-auth session; the eleven anonymous routes are marked as requiring none.
- **AC-5**: `POST /conversation/turn` and `POST /beta/plan` are documented as `text/event-stream`, each with a table of its event sequence in the route description.
- **AC-6**: Neither artifact contains a `servers` block or any api origin.
- **AC-7**: `docs/api/README.md` is written by the same script from the same in memory document, and renders the whole surface readably on GitHub with no viewer.
- **AC-8**: `npm run check:openapi` fails when the registry and the controllers disagree about which routes exist, or about a route's auth marking, naming the offending route.
- **AC-9**: `npm run check:openapi` fails when either committed artifact differs from a fresh generation.
- **AC-10**: `npm run check:openapi` fails when a controller route binds `@Body`, `@Param` or `@Query` without a `ZodValidationPipe`, naming the handler.
- **AC-11**: The check reads committed files only. No network, no database, no environment variable, so it runs on fork pull requests like every other check in the `verify` job.
- **AC-12**: `info.version` is a constant in the generator. Regenerating against an unchanged tree produces byte identical artifacts.
- **AC-13**: Rate limiting appears as 429 and 503 responses on the routes that can emit them, plus a prose description of the limiting model in the document description. No numeric limit or window is copied into the document.
- **AC-14**: The three `/grade/*` routes are marked as conditional on `GRADE_GAME_ENABLED`, which gates whether `GradeModule` is registered at all.

## Decision

**Chosen option**: Option 1: generate from zod, hand authored route registry, CI check.

Build one script that emits `docs/api/openapi.json` and `docs/api/README.md` from the zod contracts plus a registry, and one check that fails on three kinds of drift: registry against controllers, artifacts against a fresh generation, and any route binding input without a validation pipe.

**Implementation skills**: `javascript-typescript-jest` (`github/awesome-copilot`, `~/.claude/skills/javascript-typescript-jest/`)

## Feature design

**Data model sketch**:

This feature persists nothing, adds no entity and needs no migration. Its one structure is the registry entry, held in code:

| Field | Type | Required | Notes |
|---|---|---|---|
| `method` | `'get' \| 'post' \| 'patch'` | yes | compared against the controller decorator |
| `path` | string | yes | OpenAPI form, for example `/grade/problems/{publicId}` |
| `anonymous` | boolean | yes | compared against the presence of `@AllowAnonymous` |
| `summary` | string | yes | one line, rendered as the route heading |
| `description` | string | no | prose, including SSE event tables and coercion notes |
| `requestSchema` | zod schema reference | no | a named export of `@portfolio/shared` |
| `paramSchema` | zod schema reference | no | a named export of `@portfolio/shared` |
| `responses` | list of status plus shape plus description | yes | hand authored |
| `conditionalOn` | string | no | for example `GRADE_GAME_ENABLED` |
| `fieldNotes` | map of field name to string | no | fidelity notes rendered into the description |

**State transitions**: none. There is no stateful entity.

**Command surface**:

| Command | Effect |
|---|---|
| `npm run build:openapi --workspace=apps/api` | writes `docs/api/openapi.json` and `docs/api/README.md` |
| `npm run check:openapi --workspace=apps/api` | the three drift assertions; exits non zero with the offending route or handler named |

**API surface** (the surface the document must describe; the registry contains exactly these rows):

| Endpoint | Method | Key inputs | Key outputs | Auth | Key errors |
|---|---|---|---|---|---|
| `/` | GET | none | greeting string | anonymous | none |
| `/health` | GET | none | `{ status }` | anonymous | none |
| `/stories` | GET | none | story list | anonymous | none |
| `/topics` | GET | none | topic list | anonymous | none |
| `/beta/status` | GET | none | availability and counters | anonymous | 429 |
| `/beta/plan` | POST | `betaPlanRequestSchema` | `text/event-stream` | anonymous | 400, 429, 503 |
| `/conversation/turn` | POST | `conversationTurnRequestSchema` | `text/event-stream` | anonymous | 400, 429, 500 |
| `/feedback` | POST | `createFeedbackSchema` | accepted | anonymous | 400, 429 |
| `/grade/problems` | GET | none | ordered public ids and a count | anonymous | 429 |
| `/grade/problems/{publicId}/image` | GET | `gradeProblemIdParamSchema` | presigned image url | anonymous | 400, 404, 429 |
| `/grade/guess` | POST | `gradeGuessRequestSchema` | reveal and histogram | anonymous | 400, 404, 429 |
| `/internal/usage/summary` | GET | none | usage summary | session | 401 |
| `/internal/grade-photos` | GET | none | photo pool list | session | 401 |
| `/internal/grade-photos` | POST | `createGradePhotoSchema` plus multipart file | created item | session | 400, 401, 413 |
| `/internal/grade-photos/{id}/active` | PATCH | `gradePhotoIdParamSchema`, `setPhotoActiveSchema` | updated item | session | 400, 401, 404 |

**Value sourcing**:

| Action | Value produced | Source |
|---|---|---|
| Generate a request schema | the JSON Schema body | `z.toJSONSchema()` on the named export in `contracts.ts` |
| Generate a request schema | `additionalProperties: false` | the `.strict()` already on every contract object |
| Build the path list | method and path | the registry, compared against the controller decorators |
| Build the path list | auth marking | the registry, compared against the presence or absence of `@AllowAnonymous` |
| Build the path list | the `/grade/*` conditional note | the registry, recording the `GRADE_GAME_ENABLED` gate read in `app.module.ts` |
| Describe a response | success status and body shape | hand authored in the registry, taken from the service return type |
| Describe a validation failure | the 400 body | one shared component, matching `ZodValidationPipe`'s BadRequestException, whose `message` is an array of strings |
| Describe an upload failure | the 413 on `POST /internal/grade-photos` | hand authored, from `MulterErrorFilter` and `MAX_UPLOAD_BYTES` |
| Describe limiting | 429 and 503 responses | hand authored per route |
| Describe limiting | the prose model | the document description; no numeric limit is copied from `@Throttle` |
| Describe an SSE route | the event sequence table | hand authored in the route description |
| Note coercion | that `trueGrade` and `active` accept strings | a `fieldNotes` entry, rendered into the description; the generated schema alone says integer and boolean |
| Stamp the document | `info.version` | a constant in the generator, bumped by hand |
| Stamp the document | `info.title` and description | constants in the generator |
| Render the Markdown | every section | the same in memory document object the JSON is written from, so the two cannot disagree |

**Key invariants**:

- No request shape is ever hand written. Every one traces to a zod export.
- No numeric rate limit or window reaches either artifact.
- Neither artifact contains a `servers` block or an api origin.
- A regeneration against an unchanged tree is byte identical.
- The registry and the controller scan agree on the route set and on every auth marking.
- The check needs no network, no database and no environment variable.

**Security model**:

Both artifacts are public by construction: merging publishes them. Neither contains visitor data, credentials, or the api origin.

The four `/internal/*` routes are named and marked as requiring a better-auth session. This reveals nothing new, since they are already readable in the public controllers. The auth marking check exists so the document cannot come to claim one of them is anonymous, which would be a false security statement in a public file.

`POST /beta/plan`'s request schema names injury areas, symptoms and pain behaviours. These are field names and enum values already public in `contracts.ts` and already visible in the web form. No clinical guidance, no model output and no visitor content reaches the document.

better-auth's own mounted handler routes are not Nest controller routes, so neither the registry nor the controller scan sees them. They are out of scope, and the document description says so rather than implying the surface is complete.

**Configuration required**: none. No new environment variable, secret or credential.

**Critical test scenarios**:

- Happy path: `build:openapi` on a clean tree writes both artifacts and `check:openapi` passes, verifies **AC-1**, **AC-7**, **AC-9**.
- Failure case, route drift: a controller route with no registry entry fails the check with the route named, verifies **AC-8**.
- Failure case, stability: `build:openapi` run twice produces identical bytes, verifies **AC-12**.
- Failure case, unvalidated input: a handler binding `@Body` with no `ZodValidationPipe` fails the check with the handler named, verifies **AC-10**.
- Auth/permission: a registry entry whose auth marking disagrees with its `@AllowAnonymous` state fails the check, verifies **AC-4**, **AC-8**.
- Isolation: the check completes with no environment variables, no database and no network, verifies **AC-11**.

## Build plan

Ordered as a Tracer Bullet: a working thread through every layer of this feature first (script, generation, both artifacts, output location), then breadth, then the check that guards it.

1. Thin thread. `apps/api/scripts/build-openapi.ts` run through `tsx`, wired as `build:openapi`, emitting a valid OpenAPI 3.1 document and its Markdown rendering into `docs/api/` for one route only, `GET /health`, with `info.version` as a constant. Satisfies **AC-1**, **AC-7**, **AC-12**.
2. Registry module at `apps/api/src/openapi/route-registry.ts` with the entry shape above, populated for all 15 routes, including the `/grade/*` conditional marking. In `src/` and not `scripts/` because jest will not collect `scripts/`. Satisfies **AC-1**, **AC-4**, **AC-14**.
3. Generate every request body and parameter schema from the zod exports via `z.toJSONSchema()` at target `draft-2020-12`, with `fieldNotes` rendered into the descriptions for the coercing fields. Satisfies **AC-2**.
4. Hand author responses and errors per route in `route-registry.ts`, including the one shared 400 component and the 429 and 503 markings, plus the prose limiting model in the document description. Satisfies **AC-3**, **AC-13**.
5. SSE routes, in `route-registry.ts`: `text/event-stream` plus the event sequence table for `POST /conversation/turn` and `POST /beta/plan`. Satisfies **AC-5**.
6. Internal routes: declare the session security scheme in `build-openapi.ts` and mark the four routes against it. Satisfies **AC-4**.
7. Controller scan at `apps/api/src/openapi/controller-scan.ts` with colocated `.spec.ts`, reading route decorators, `@AllowAnonymous`, and input bindings with their pipes. Satisfies **AC-8**, **AC-10**.
8. `apps/api/scripts/check-openapi.ts` wired as `check:openapi`, asserting all three kinds of drift and naming the offender in each failure, reading committed files only. Satisfies **AC-8**, **AC-9**, **AC-10**, **AC-11**.
9. Add the check to the `verify` job in `.github/workflows/ci.yml`, beside `check:corpus`. Satisfies **AC-9**.
10. Confirm both artifacts carry no `servers` block and no api origin, and link `docs/api/` from the root README. Satisfies **AC-6**, **AC-7**.

## Consequences

**Positive**:

- The public repository gains a legible description of its api surface, with no runtime endpoint, no new dependency and no served UI to operate.
- Request shapes are published exactly as enforced, including `additionalProperties: false`, because they come from the schemas that do the enforcing.
- A route added without any validation becomes a build failure rather than a silently unvalidated endpoint, closing a hole the code currently documents as an accepted tradeoff.
- A false claim about which routes need authentication becomes a build failure.

**Negative / tradeoffs**:

- The registry is a second description of method, path, auth and responses. The check makes it safe, not free: every route change now edits two places.
- Responses stay hand authored, so only the request half is protected from drift. The document can describe a response shape that the service no longer returns.
- The document is slightly wrong at two known points unless the notes are read: `trueGrade` and `active` are generated as integer and boolean although both arrive as strings over multipart and query, and any `.refine()` flattens to its base type because JSON Schema cannot express it.
- One more step in `verify`, and one more way for CI to go red on a change that is otherwise correct.
- A zod minor version bump can change `toJSONSchema` output and fail the check with no api change at all. The fix is a regeneration, but the failure will look alarming the first time.

**Neutral**:

- `docs/api/` becomes a fourth class of committed generated artifact, alongside the skills layout, the published evals record and the retrieval corpus.
- `packages/shared` must be built before the generator runs. The root `postinstall` already does this, so a fresh clone and CI both work without anyone remembering.
- `info.version` starts a small versioning discipline that nothing else in the repository currently practises.
